## 8. What the Software Does on Your Machine

So that you can decide with full information, this is everything the Software does when you run a scan:

1. It reads files and system information on the machine it runs on, for pattern matching only. These may include sensitive files such as `/etc/passwd`, `/etc/shadow` (when run as root), sudo rules, SSH, firewall and web server configuration, systemd service unit files, kernel parameters, package lists, and application configuration files for stacks such as Apache Tomcat, Node.js, Django, Flask, WordPress, Joomla and Drupal, which can contain passwords or secret keys. In full, the files and folders read also include: the boot loader configuration (GRUB files including user.cfg) and the firmware Secure Boot variables under `/sys/firmware/efi/efivars`; the audit daemon configuration and rules and the journald configuration; the PAM stacks, `/etc/login.defs` and root's shell start-up files; container runtime configuration for Docker, containerd and Podman, the Docker socket's ownership and permissions, and each container's `hostconfig.json` and `config.v2.json`; nginx and Apache configuration trees; MySQL or MariaDB, PostgreSQL (including `pg_hba.conf`), Redis and MongoDB configuration; Postfix, Dovecot and BIND configuration; application framework files such as `.env`, Django and Rails settings and key paths; cron tables and cron folders; `authorized_keys` files of root and of user accounts; and a bounded walk of `/etc` and of each web document root (file names and permissions, then the contents of at most 300 world-readable configuration-like files) matched against credential patterns, where only the file name and the kind of pattern are recorded and no matched value is ever copied. The checks look only for weak settings and are designed never to copy secret values into a report.
2. It runs only a fixed allow-list of read-only commands, including `sshd -T`, `apt-get -s upgrade` (simulation only), `dnf` or `yum updateinfo`, `rpm -qa`, firewall status commands (`nft`, `iptables`, `ip6tables`, `ufw`, `firewall-cmd`), `systemctl is-active` and `systemctl is-enabled`, `uname -r`, `node --version`, `php -v` and `php -r` limited to reading configuration values. It compares the firewall rules with the services that are actually listening. The full list is in the source code (`internal/sys`), and `openvapt scan --dry-run` previews every action.
3. It sends ordinary HTTP GET requests and TLS handshakes to the websites and services on the same machine, only through loopback addresses (127.0.0.0/8 and ::1), including requests for a short list of fixed paths such as `/.git/HEAD`, `/.env`, `/phpinfo.php` and common administration pages to see whether they are exposed. These requests may appear in your web server logs and may trigger your security tools.
4. It is designed not to change, delete, install, restart, exploit, attack or brute-force anything, and in its unmodified form it is designed to make no connection to any other machine. Software can contain mistakes, so you must not treat this design as a promise.
5. It uses CPU, memory and disk time while it runs. Each check has a time limit and work is bounded, but on a busy or fragile server even read-only activity can have side effects.
6. It writes a report, which describes weaknesses of your machine, to a folder you choose, readable only by your user account. As a second safeguard, the report is also redacted by pattern matching, which may not catch everything. Protecting and sharing the report is your responsibility.
7. If you enable signing (the default), it creates a private key on your machine in your user configuration folder (for root, under root's home). Keep it private.
