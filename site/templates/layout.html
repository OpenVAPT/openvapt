Why it matters: Root is the one account name every attacker knows. Allowing it over SSH turns any password guess into full control of the server, and removes the audit trail of which person used root.

Evidence, sshd: Root may log in over SSH with a password

Fix: In /etc/ssh/sshd_config set: PermitRootLogin no (or prohibit-password if key-based root login is truly required). Log in as a named user and use sudo. Then run: sshd -t && systemctl reload sshd

This is a simulated walkthrough using the built-in demo lab. It is built only from real OpenVAPT output; long output is trimmed where marked and every value is kept as printed.

  1. Install. Run curl -fsSL https://raw.githubusercontent.com/OpenVAPT/openvapt/main/scripts/install.sh | sh. The installer downloads the Linux binary and SHA256SUMS, verifies the checksum, checks the Sigstore signature when cosign is installed, and installs to ~/.local/bin without root. It prints: "Installed. Nothing has been scanned."
  2. Accept. Run sudo openvapt scan --out ~/openvapt-report. OpenVAPT prints the terms and ten numbered acknowledgements, then asks you to type I ACCEPT; anything else cancels and nothing is stored. It then prints "Scanning this machine with 307 checks (read-only, local only)...".
  3. Checks. The read-only checks cover three domains: Server (for example HOST-SSH-001, HOST-USR-003, HOST-KRN-001), Network (NET-DB-002, NET-FW-001, NET-TLS-001) and Web (WEB-EXP-002, WEB-HDR-002). The terminal prints only the start line and the summary; the scene illustrates the work in between.
  4. Summary. openvapt demo scans a simulated vulnerable lab server in memory: 307 checks run, 2 passed, 305 failed, 0 incomplete; failed by severity Critical 14, High 71, Medium 88, Low 123. It writes report.html and report.md only on this machine and exits with code 3, meaning findings at or above High severity were found.
  5. Report. The HTML report has an executive summary, severity counts and a card for each finding. The HOST-SSH-001 card shows the evidence permitrootlogin yes, the fix (set PermitRootLogin no, then sshd -t && systemctl reload sshd), how to verify it, and the Academy module P2: SSH Security. Secrets in evidence are redacted before the report is written.
  6. Explain and Learn. openvapt explain HOST-SSH-001 prints what the check does, why it matters, how it detects, how to fix and verify it, and its references. openvapt learn lists the offline Academy: 3 Foundations, 22 Practitioner and 6 Applied modules, each with a quiz.
  7. Next. Download OpenVAPT or start the Academy.
