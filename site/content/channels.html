How a Build Is Promoted

1
Plan

Every day the promote workflow finds the most mature channel whose history, time and legal gates pass, and the exact commit that would move up.

2
Verify

That exact commit runs the full CI suite, the lab proof and the installer test again. Nothing tested on another commit counts.

3
Release

The build is published with checksums, Sigstore signatures, build provenance and an SBOM. Alpha, Beta and Release Candidate are marked pre-release.

4
Record

Every gate is checked once more with the real evidence, and the promotion is appended to the public record. Records are never edited.

Gate logic: internal/channels/channels.go. Workflow: .github/workflows/promote.yml. Record: release/channels.json.

Choosing a Channel

Use Stable once it exists. Use Release Candidate, Beta or Alpha only on test machines, to help find problems before Stable. The installer picks Stable by default; see Download for every channel's install command. openvapt version prints the channel of the build you run, and every report records it.
