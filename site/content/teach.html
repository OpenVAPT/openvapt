For Teachers

Teach vulnerability assessment from theory to practice, free. OpenVAPT gives you ready course plans, printable worksheets with answer keys, a marking rubric and a simulated practice server chosen by each student's seed. Before Your First Class

  1. Read Teaching With OpenVAPT and the EULA, and follow the teacher's checklist in the teaching terms.
  2. Brief students on the law and ethics first: assessing a system without authorisation is an offence under the Computer Crimes Act 1997. The Academy's module F2 covers this.
  3. Decide where students work: the website and your projector demo only, the built-in simulated lab, or isolated lab machines your institution owns or controls and has authorised. Never a third party's system. A student may also run OpenVAPT on a computer the student personally owns or controls, but that is the student's own Own Use, not part of your class: do not run it on a student's machine for them or make it a requirement.
  4. Every student who downloads or runs OpenVAPT reads and accepts the acknowledgements personally. You may not accept for them, and you may not tell them to use --accept-terms. Students under 18 may download or run OpenVAPT only after a parent or guardian has accepted the EULA for them; otherwise they use only the website Academy and watch your demonstration.
  5. OpenVAPT is pre-release software (see Release Channels). It may be wrong or unstable. Use it only on isolated lab machines, 100% at your own risk, and remember that a clean report does not prove a system is secure.

Practice Labs: A Different Server for Every Student

A practice server is the simulated vulnerable lab with some weaknesses fixed. The seed decides which ones, check by check, so every student is likely to assess a different server, which makes copying a neighbour's report much harder. The same seed gives the same server in the same version of OpenVAPT. The practice lab is simulated in memory and is not run against a real machine.

Student

openvapt demo --lab practice --seed <student-number> --out my-report

The student reads the report, verifies each finding, rates it, writes fixes and submits an assessment report, marked with the rubric below.

Teacher

openvapt teach answers --seed <student-number>

Prints the list of weaknesses planted on that student's simulated server, with severity and category, as a Markdown table for marking.

{{icon "triangle-alert"}}Limitation: the answer key is computed by the same public code every student has, so any student can print the answer key for their own seed or anyone else's. Treat practice labs as learning exercises, not secure exams. For graded work, combine them with written questions, the student's own evidence and a short oral explanation of findings. The key lists what the lab planted; it is not proof that a report is complete or correct.

Lab Recipe

Three ways to give students something to assess, from no setup to a full lab, each labelled by what exists today.

ExistsNo Setup

Simulated Lab: openvapt demo

Two servers live in memory inside the tool: one deliberately misconfigured, one hardened. Nothing is installed, listened on or written except the report folder you name.

openvapt demo --out demo-report
openvapt demo --lab hardened --out demo-hardened
openvapt diff demo-report demo-hardened

Classroom use: project the vulnerable report, pick three findings, and ask what the hardened report shows for each.

ExistsOne Server per Student

Practice Lab With a Seed

The practice lab is the vulnerable server with a seed-chosen set of weaknesses fixed, so each student assesses a different server. The teacher prints the planted weaknesses for any seed.

openvapt demo --lab practice --seed 42 --out s42
openvapt teach answers --seed 42

Still simulated in memory; see the limitation below about answer keys being public.

PlannedNot Yet Available

Lab Image for Virtual Machines

A ready-made Linux virtual machine image with the same misconfigurations as the simulated vulnerable server, so a class can assess, fix and re-scan a real machine on an isolated lab network.

This is planned work and does not exist yet. Until it does, build your own: install a supported Linux on an isolated virtual machine your institution owns, apply the settings each failed demo check describes, snapshot it, and let students harden it and scan again.

Setting Up a Lab

  • No setup: the website Academy and openvapt demo run on any computer and touch nothing.
  • Institution lab: isolated virtual machines on infrastructure your institution owns or controls, on a lab network with no route to production or third-party systems. Snapshot each machine so students can harden it and start again.
  • Before scanning a lab machine: record the authorisation, run openvapt scan --dry-run to preview every file, command and request, then scan with sudo openvapt scan --out report.
  • Install: build from source (recommended for teaching how the tool works) or use the installer on the Download page.
