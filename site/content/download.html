Get OpenVAPT

There are three ways. Building from source is recommended: you run exactly the code you can read, it needs nothing but Go, and building it is part of learning how it works. The one-command installer and the ready-made binaries are conveniences, built publicly from the same source and verified before use.

RecommendedMost Transparent

Option 1: Build From Source

Read the code, then build it yourself. OpenVAPT uses only the Go standard library, so nothing else is downloaded or trusted.

OptionalFastest

One line downloads the binary for your CPU, verifies its checksum and signature, and installs it without root. It scans nothing unless you ask.

For machines without Go. Built only by GitHub Actions from a public tagged commit, with checksums, Sigstore signatures, build provenance and a software bill of materials.

Option 1: Build From Source (Recommended)

You need Go 1.26 or newer; go.mod pins the Go 1.26.9 toolchain and Go downloads it automatically if needed. Get the source with git, or download a source archive from the GitHub repository or a release.

# 1. Get the source
git clone https://github.com/OpenVAPT/openvapt.git
cd openvapt

# 2. Read it (start with README.md, internal/scope and internal/sys)

# 3. Run the tests, including the simulated lab tests
go test ./...

# 4. Build a single static binary
CGO_ENABLED=0 go build -trimpath -o openvapt ./cmd/openvapt

# 5. Read the acknowledgements again, then check the version
./openvapt terms
./openvapt version

To build exactly a released version, check out its tag first, for example git checkout v{{$d.CiteVersion}} (the newest released build; see Release Channels for every channel). To build the same bytes as the official release binary, use the same Go version and flags as the release (shown in its release notes and in the Makefile):

git checkout v{{$d.CiteVersion}}
make release VERSION=v{{$d.CiteVersion}}
sha256sum dist/release/openvapt_linux_amd64   # compare with the published SHA256SUMS

Option 2: One-Command Install (Optional)

{{icon "info"}}Works once the chosen channel has a release. Until then the installer stops and lists the channels that have one.

Read the script first: scripts/install.sh. It checks that the machine is Linux on amd64 or arm64, downloads the release binary and SHA256SUMS from GitHub Releases, refuses to install if the SHA-256 checksum does not match, also verifies the Sigstore signature when cosign is installed, and installs to ~/.local/bin (or /usr/local/bin as root). It sends nothing anywhere and scans nothing.

curl -fsSL https://raw.githubusercontent.com/OpenVAPT/openvapt/main/scripts/install.sh | sh

The installer downloads only over HTTPS with TLS 1.2 or newer, including redirects. When cosign is missing it continues with the checksum alone; to refuse installation unless the Sigstore signature is verified, set OPENVAPT_REQUIRE_SIGNATURE=1:

curl -fsSL https://raw.githubusercontent.com/OpenVAPT/openvapt/main/scripts/install.sh | OPENVAPT_REQUIRE_SIGNATURE=1 sh

The installer installs Stable by default. To test a pre-release on a test machine, choose a channel with --channel. Current builds per release channel:

curl -fsSL https://raw.githubusercontent.com/OpenVAPT/openvapt/main/scripts/install.sh | sh -s -- --channel beta

To install and then start an interactive scan of this machine in the same command, add --run. The scan still shows the acknowledgements and continues only when you type I ACCEPT; the installer never accepts for you.

sh -c "$(curl -fsSL https://raw.githubusercontent.com/OpenVAPT/openvapt/main/scripts/install.sh)" -- --run

Options: --channel picks stable, rc, beta or alpha, --version vX.Y.Z installs a specific release, --dir DIR chooses the folder. Piping a script into a shell trusts whoever serves it; if you prefer, download it, read it, then run it:

curl -fsSLo install.sh https://raw.githubusercontent.com/OpenVAPT/openvapt/main/scripts/install.sh
less install.sh
sh install.sh

Option 3: Verified Linux Binary (Optional)

{{icon "info"}}Releases appear on the GitHub Releases page, built only through the promotion workflow after every channel gate passed, with SHA256SUMS, a .sigstore.json signature bundle per binary, build provenance, a source archive and an SBOM. Always verify before running.
sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob --certificate-identity-regexp '^https://github\.com/OpenVAPT/openvapt/\.github/workflows/release\.yml@refs/heads/main$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --bundle openvapt_linux_amd64.sigstore.json openvapt_linux_amd64
gh attestation verify openvapt_linux_amd64 --repo OpenVAPT/openvapt \
  --signer-workflow OpenVAPT/openvapt/.github/workflows/release.yml

Try It Safely First

./openvapt demo                    # scans a simulated vulnerable server, in memory
./openvapt scan --dry-run          # lists every file, command and request a real scan would use
./openvapt learn                   # the OpenVAPT Academy, offline
./openvapt explain HOST-SSH-001    # documentation for one check

Scan Your Own Linux Machine

sudo ./openvapt scan --out ~/openvapt-report

Before every scan the tool shows the acknowledgements again and continues only when you type I ACCEPT (or you pass --accept-terms for automation, which counts as the same acceptance). Running as root lets checks read protected files such as /etc/shadow; without root those checks are skipped or marked Incomplete. The report is written only to the folder you choose, with private permissions. Exit codes: 0 success, 2 invalid arguments, 3 Critical or High findings, 4 incomplete coverage, 5 scan errors, 6 report write failure.

Cite OpenVAPT

If OpenVAPT helps your coursework, thesis, paper or project, please cite the version you used (openvapt version). Copy a ready-made reference from How to Cite OpenVAPT or read Citing OpenVAPT.

Uninstall

OpenVAPT installs nothing beyond its own binary. Delete the binary (rm ~/.local/bin/openvapt if you used the installer) and your report folders. If you signed reports, also delete ~/.config/openvapt/report-key.
